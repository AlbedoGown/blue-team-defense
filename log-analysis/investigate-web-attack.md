# Кейс: Investigate Web Attack — разведка и веб-атака по access-логу

**Категория:** Log Analysis / Web Attack Detection
**Платформа:** [LetsDefend — Investigate Web Attack](https://app.letsdefend.io/challenge/investigate-web-attack)
**Инструменты:** ручной разбор access-лога (Apache/nginx combined log), сигнатуры сканеров, regex

## Обзор

Расследование по сырому access-логу веб-сервера, обслуживающего уязвимое учебное приложение **bWAPP** (`/bWAPP/`). Задача — восстановить хронологию атаки: с чего начал злоумышленник, какими инструментами пользовался, что именно эксплуатировал.

## Окружение

- Целевой хост в логе: `192.168.199.5` (bWAPP)
- IP из лога, связанные с активностью: `192.168.199.1`, `192.168.199.2`
- Формат лога: Apache/nginx combined (`IP - - [время] "METHOD path HTTP/ver" статус размер "referer" "user-agent"`)

## Шаг 1. Инструмент автоматической веб-разведки

**Вопрос:** Какой инструмент автоматического сканирования использовал злоумышленник для веб-разведки?

Фрагмент лога, где начинается активность второго IP (`192.168.199.2`):

```
192.168.199.2 - - [20/Jun/2021:12:36:24 +0300] "HEAD / HTTP/1.1" 200 - "-" "Mozilla/5.00 (Nikto/2.1.6) (Evasions:None) (Test:Port Check)"
192.168.199.2 - - [20/Jun/2021:12:36:24 +0300] "GET /bwapp/ HTTP/1.1" 302 "-" "Mozilla/5.00 (Nikto/2.1.6) (Evasions:None) (Test:getinfo)"
192.168.199.2 - - [20/Jun/2021:12:36:24 +0300] "GET /bwapp/ HTTP/1.1" 302 "-" "Mozilla/5.00 (Nikto/2.1.6) (Evasions:None) (Test:map_codes)"
192.168.199.2 - - [20/Jun/2021:12:36:24 +0300] "GET /bwapp/4RaXX5Ac.exe HTTP/1.1" 404 300 "-" "Mozilla/5.00 (Nikto/2.1.6) (Evasions:None) (Test:map_codes)"
192.168.199.2 - - [20/Jun/2021:12:36:24 +0300] "GET /bwapp/4RaXX5Ac.show HTTP/1.1" 404 300 "-" "Mozilla/5.00 (Nikto/2.1.6) (Evasions:None) (Test:map_codes)"
...
```

**Ответ: Nikto** (версия 2.1.6).

Признаки, по которым это определяется однозначно, а не предположительно:

1. **User-Agent прямо называет инструмент** — `Mozilla/5.00 (Nikto/2.1.6) (Evasions:None) (Test:...)`. Это не подделанный UA под браузер — Nikto по умолчанию честно представляется, если не включена маскировка.
2. **Формат UA специфичен для Nikto** — сегменты `(Evasions:...)` и `(Test:...)` не общая практика, а особенность конкретно Nikto: он вписывает в свой же User-Agent название текущей выполняемой проверки (`Port Check`, `getinfo`, `map_codes`) и статус техник обхода детекта (evasions). Инструмент вроде dirb/gobuster так не делает.
3. **`Test:map_codes` со случайным именем файла** (`4RaXX5Ac.exe`, `4RaXX5Ac.show`, `4RaXX5Ac.java`...) — это узнаваемая техника самого Nikto: он запрашивает заведомо несуществующий путь со случайным именем и разными расширениями, чтобы понять, как сервер обрабатывает 404 (нет ли кастомной страницы ошибки, которая маскирует реальные результаты сканирования под "не найдено").
4. **Темп запросов** — множество запросов в одну и ту же секунду (`12:36:24`) с одного IP — не то, как ведёт себя человек в браузере, характерно для автоматизированного инструмента.

## Шаг 2. Метод обнаружения содержимого каталогов

**Вопрос:** После проведения веб-разведки, какой метод использовал злоумышленник для обнаружения содержимого каталогов?

Фрагмент лога — тот же IP (`192.168.199.2`), уже после сканирования Nikto:

```
192.168.199.2 - - [20/Jun/2021:12:38:02 +0300] "GET /bwapp/admin/2004 HTTP/1.1" 404 300 "-" "Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)"
192.168.199.2 - - [20/Jun/2021:12:38:02 +0300] "GET /bwapp/admin/2005 HTTP/1.1" 404 300 "-" "Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)"
...
192.168.199.2 - - [20/Jun/2021:12:38:02 +0300] "GET /bwapp/admin/2014 HTTP/1.1" 404 300 "-" "Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)"
192.168.199.2 - - [20/Jun/2021:12:38:02 +0300] "GET /bwapp/admin/21 HTTP/1.1" 404 300 "-" "Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)"
```

**Ответ: Directory/Content Brute-Forcing (Forced Browsing)** — перебор каталогов по словарю/списку значений в поисках существующих, но не проиндексированных путей.

Уточнение по коду ответа: в логе **404 Not Found**, не 400 — 400 означало бы, что сам запрос синтаксически некорректен (проблема на стороне клиента в формировании запроса), тогда как 404 означает "запрос корректен, но такого ресурса на сервере нет". Именно 404 и подтверждает вывод: перебираемые пути `/bwapp/admin/2004`...`/bwapp/admin/2014`, `/bwapp/admin/21` — не существуют, атакующий просто перебирает кандидатов.

Дополнительные наблюдения по этому фрагменту:

- **User-Agent сменился** — теперь `Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)`, вместо явного `Nikto/2.1.6` из Шага 1. Это либо сам Nikto с изменённым/дефолтным UA для отдельного модуля брутфорса, либо отдельный инструмент directory-брутфорса (например Dirbuster/wfuzz с кастомным UA), запущенный тем же атакующим с того же IP. Явной сигнатуры инструмента в самом UA здесь уже нет — только по паттерну запросов (перебор коротких числовых путей под `/bwapp/admin/`) видно, что это автоматизированный брутфорс, а не Nikto-специфичный скан.
- Все запросы в один и тот же timestamp (`12:38:02`) — снова темп, невозможный для ручного перебора человеком.

## Выводы (промежуточные)

- User-Agent — первое, что стоит проверять при подозрении на автоматическое сканирование, но важно уметь отличить "просто упомянутое имя инструмента" от **структурных** признаков конкретно этого инструмента (для Nikto — формат `(Evasions:X) (Test:Y)`), чтобы не полагаться только на строку, которую легко подделать.
- `Test:map_codes` со случайным именем файла — полезная сигнатура для детект-правила: запрос на несуществующий путь со случайной алфавитно-цифровой строкой в имени и множеством разных расширений подряд с одного IP.
- Directory/content brute-forcing различим по паттерну путей (короткие предсказуемые сегменты — числа, общие словарные слова типа `admin`) и коду **404** на большинство запросов при единичных "попаданиях" — а не по User-Agent, который атакующий может как угодно менять между этапами атаки.
- Важно не путать коды 4xx между собой в отчётах: 400 (Bad Request) ≠ 404 (Not Found) ≠ 403 (Forbidden) — каждый говорит о разной причине отказа и по-разному читается при триаже.
