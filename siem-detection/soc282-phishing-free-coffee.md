## Расследование

### 1. Анализ письма

```
От:            free@coffeeshooop.com
Кому:          Felix@letsdefend.io
Тема:          Бесплатный купон на кофе
IP отправителя: 103.80.134.63
Дата:          2024-05-13 09:22:00
Вложение:      free-coffee.zip (пароль: infected)
Гиперссылка:   https://files-ld.s3.us-east-2.amazonaws.com/59cbd215-76ea-434d-93ca-4d6aec3bac98-free-coffee.zip
```

Красные флаги, видимые уже на этапе разбора заголовков и тела письма:

1. **Тайпсквоттинг домена** — `coffeeshooop.com` (лишняя "o"), маскировка под легитимный бренд кофейни.
2. **Давление срочностью** в тексте письма ("Спешите, срок действия этого предложения скоро истекает!") — классический приём социальной инженерии.
3. **Двойная доставка полезной нагрузки** — одновременно вложение и дублирующая гиперссылка на тот же файл. Ссылка ведёт на легитимный домен AWS S3, что используется для обхода репутационных URL-фильтров (домен `amazonaws.com` доверенный, сам вредоносный объект — по конкретному пути на нём).
4. **ZIP защищён паролем** (`infected`, указан прямо в письме) — приём для обхода сканирования вложений на email-шлюзе, так как большинство движков не могут заглянуть внутрь запароленного архива.

Проверка репутации SMTP-адреса на VirusTotal:

```
IP: 103.80.134.63
Детекты: 9/89 (теги Phishing, Malicious)
ASN: AS3786, LG DACOM Corporation (Корея)
```

**Вывод шага:** письмо доставлено с уже засвеченной вредоносной инфраструктуры, содержимое — целевой фишинг с двойным вектором доставки.

История браузера хоста:

Спустя ~3.5 часа после доставки письма (09:22 → 12:59) пользователь перешёл по ссылке и скачал архив. Остальные записи в истории (новостные сайты, вход в Outlook/Microsoft 365) — фоновый пользовательский браузинг, не связанный с атакой.

Данные исполненного процесса:

```
Хэш (SHA256):        CD903AD2211CF7D166646D75E57FB866000F4A3B870B5EC759929BE2FD81D334
```

Родительский процесс `explorer.exe` подтверждает, что файл запущен вручную — двойным кликом из папки загрузок, а не автоматически скриптом.

Проверка хэша на VirusTotal:

```
Детекты:         61/71
Классификация:   Trojan.AsyncRAT/MSIL
Family labels:   asyncrat, msil, dcrat
Внутреннее имя:  dllhost.exe (маскировка под легитимный системный процесс Windows)
Теги:            obfuscated, long-sleeps (anti-sandbox), detect-debug-environment (anti-debug)
```

**Вывод шага:** файл под вывеской "купона на кофе" — троян семейства **AsyncRAT** с техниками ухода от песочниц/отладки, запущен пользователем вручную.

## Вердикт

**True Positive, критичность High.**

Обоснование: подтверждённое исполнение вредоносного файла (AsyncRAT, 61/71 на VT) с активным C2-соединением на скомпрометированном хосте. High, а не Critical — компрометация локализована на одном хосте, подтверждённого lateral movement или доступа к критичным системам в собранных данных нет.

## Рекомендованные действия

1. **Containment** — хост Felix (`172.16.20.151`) изолирован от сети.
2. **Блокировка IOC на периметре** — IP `37.120.233.226`, домен `coffeeshooop.com`, IP `103.80.134.63` на email-шлюзе/файрволе.
3. **EDR** — хэш `Coffee.exe` (`CD903AD2...FD81D334`) добавлен в блок-лист по всей организации.
4. **Scope** — проверка почтовых логов на предмет доставки того же письма другим сотрудникам.
5. **Учётные данные** — принудительный сброс пароля Felix (AsyncRAT штатно способен красть учётные данные и вести кейлоггинг).
6. **Persistence** — проверка и устранение автозапуска/запланированных задач на хосте либо переустановка системы из чистого образа.
7. **Awareness** — информирование сотрудников о конкретной фишинговой кампании (тема, отправитель, приём с запароленным архивом).

## Выводы

- Дублирование вектора доставки (вложение + ссылка на тот же файл через доверенный облачный домен) — приём, рассчитанный на то, что хотя бы один канал пройдёт мимо фильтров: вложение может зарезать антивирус на шлюзе, ссылку на `amazonaws.com` — репутационный URL-фильтр, ориентирующийся на домен, а не на конкретный путь.
- Пароль на архиве, указанный прямо в письме — простой, но эффективный способ обхода автоматического сканирования вложений: большинство email security продуктов не могут заглянуть внутрь запароленного ZIP, а получателю пароль не создаёт никаких неудобств.
- 0 или низкое число детектов на VirusTotal для свежей полезной нагрузки не означает "чисто" — здесь итоговый файл всё же дал 61/71, но само рассуждение "надо проверить VT" должно применяться и к письмам/URL с низким числом детектов на момент доставки: вредоносная инфраструктура может ещё не попасть в базы.
- Родительский процесс `explorer.exe` у вредоносного `.exe` — надёжный индикатор ручного запуска пользователем (двойной клик), в отличие от запуска через `cmd.exe`/`powershell.exe`/офисный процесс, что указывало бы на скриптовую автоматизацию или эксплуатацию документа.
- При подтверждённом C2-соединении вывод по инциденту не ограничивается "вредоносный файл был исполнен" — нужно явно фиксировать постэксплуатационную фазу (реальный канал управления), потому что от этого зависит набор реагирования (сброс учётных данных, поиск персистентности), а не только удаление файла и информирование пользователя.
